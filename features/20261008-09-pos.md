# POS — Session-Based Point of Sale (approved)

> Status: approved spec, to implement · Module: `app/sales` (new entities) + `app/warehouse` (movement writer, guarded) + `app/product` (search + existence checks, guarded)
> Locked decisions: one active session per user/cashier; payments cash|qris|transfer|debit_credit; paper sale allowed (consistent with DO); receipt auto-prints on checkout, emailed instead when linked to a customer

Vertical-slice rule: `models/` (`toApi()` + lazy factory, `underscored:true`, `timestamps:false`) → `useCases/<entity>/` (extending `BaseUseCase`: Joi in `preExec`, `recordActivityLog`/`settleTransaction` in `postExec`) → `api/[version]/` (`export const runtime="nodejs"`, `withAuthorization(handler,[...codes])`, `ok()`/`fail()`, JSON-only `{iv,data}`) → `components/` + `views/` + `paths.ts`.

Global invariants: `organization_id` from actor, never from payload; soft delete; Joi `unknown(false)`; perms snapshot at login; dropdowns degrade via `Promise.allSettled`; submit `disabled={isPending||loading}` + guard; filters display-only; cross-module reads degrade (uuid fallback).

Totals math identical to PR/SO/DO-08 (`%`-only): `line_total = round(qty * unit_price * (1 - discount_pct/100))`, `subtotal = Σ`, `grand_total = round(subtotal * (1 - header_pct/100))`. Tendered/change computed server-side (`change = max(0, tendered - grand_total)`; non-cash methods ignore tendered).

## F-01 Session lifecycle (per cashier, midnight auto-close)

- **Open** `POST /sales/api/v1/pos-sessions/open {opening_cash?, notes?}` (perm `sales:pos-session:create:create`): if an `open` session exists for `(organization_id, opened_by=actor)` return `{session, already_open:true}` (no duplicate). Else create `{opened_by: actor.uuid, opened_at: now, status:"open"}`. Plain log.
- **Lazy midnight close** (no cron V1): `open` and `ship/sale` `preExec` run `closeStaleSessions(orgId)` — any `open` session with `opened_at < today 00:00 (server TZ)` flips to `{status:"auto_closed", closed_at: midnight}` + activity log. New shift then opens fresh. (Dedicated scheduler is a later optimization, same semantics.)
- **Close** `POST /sales/api/v1/pos-sessions/:uuid/close {closing_cash?, closing_note?}` (perm `sales:pos-session:view:close`): only the active session; owner-only (actor must equal `opened_by`; admins override via explicit `force:true` + separate perm note — owner-only enforced, 403 otherwise). Plain log.
- **POS entry check:** opening the POS page calls `open` (idempotent join-or-create) — the cashier always lands in *their* session, never someone else's.

```ts
Joi open: { opening_cash: Joi.number().integer().min(0).default(0), notes: Joi.string().trim().allow("", null).optional() }
Joi close: { closing_cash: Joi.number().integer().min(0).allow(null).optional(), closing_note: Joi.string().trim().allow("", null).optional(), force: Joi.boolean().default(false) }
```

## F-02 Sale (billing-gated, stock-deducting, customer optional)

`POST /sales/api/v1/pos-transactions` (perm `sales:pos-transaction:create:create`):

```ts
const posItem = Joi.object({
  product_id: Joi.string().uuid({version:"uuidv4"}).required(),
  variant_id: Joi.string().uuid({version:"uuidv4"}).allow(null).optional(),
  qty: Joi.number().integer().min(1).required(),
  unit_price: Joi.number().integer().min(0).required(), // client-supplied (shelf price)
  discount_pct: Joi.number().min(0).max(100).default(0),
});
Joi.object({
  session_id: Joi.string().uuid({version:"uuidv4"}).required(),
  customer_id: Joi.string().uuid({version:"uuidv4"}).allow(null).optional(), // walk-in when null
  warehouse_id: Joi.string().uuid({version:"uuidv4"}).required(),
  payment_method: Joi.string().valid("cash","qris","transfer","debit_credit").required(),
  tendered: Joi.number().integer().min(0).allow(null).optional(),
  discount_pct: Joi.number().min(0).max(100).default(0),
  fulfillment: Joi.string().valid("system","paper").default("system"),
  items: Joi.array().items(posItem).min(1).max(200).required(),
}).unknown(false);
```

- `preExec`: lazy-close stale sessions → require `session_id` open + owned by actor (403 otherwise) → `checkTransaction(actor,"sales:pos-transaction:create:create")` → customer same-org when provided (404/403) → product/variant existence via guarded import (absent module → skip, store uuids).
- `execute` (DB transaction): snapshot totals → create transaction + items → system path: availability per line (`on_hand - reserved`, 422 short-stock aborts whole sale) → `insertMovementRow` per line `{type:"out", ref_type:"pos-transaction", ref_id: txn_uuid}` → `fulfillment=system, stock_deducted=true`. Paper path (`fulfillment=paper` requested, or warehouse module absent): no warehouse touch → `fulfillment=paper, stock_deducted=false` + receipt flag ("stock not deducted", postable later via re-post endpoint like DO).
- `postExec`: one `settleTransaction(operation:"create", entity:"pos_transaction")` per completed sale (paper and system alike); failed 422 charges nothing. Then receipt dispatch (F-05): `customer_id` null → `receipt_channel=print` (client auto-prints); set → `receipt_channel=email` + send via Mailgun (failure never fails the sale — see F-05).
- **Void** `POST .../pos-transactions/:uuid/void {reason}` (perm `view:void`, completed→voided only): when `stock_deducted=true` writes counter `in` movements (`ref_type:"pos-void"`); paper voids just flip status. No second settle.
- **Decided (2026-10-09 test finding):** a void restores the finished-good line only — BoM component `out` legs intentionally stay consumed (void = goods returned after components were spent, not a time-reversed sale). Reversing components would also use the *current* BoM, which may differ from sale time. Component-level reconciliation, if ever needed, is a stocktake/`adjust` flow, not void.

## F-04 POS UI (`views/pos/`)

Server page (perm `sales:pos-transaction:create:create`) → `PosClient`: left = search + product grid (price + available-stock badge, degraded when warehouse absent); right = cart (qty steppers, per-line % discount), customer picker (optional, `filter[q]`, walk-in default), payment method radio (cash shows tendered/change), fulfillment toggle (system/paper with paper warning), Pay button (`disabled` while paying/loading). Success → receipt view (F-05) + New sale. Session bar shows owner/shift start + Close-shift button.

## F-05 Receipt: auto-print vs customer email

Rule: walk-in (`customer_id` null) → browser auto-prints; linked customer → no print, receipt emailed to `customer.email` instead.

- **Receipt number:** server-generated per org (`POS/{YYYY}/{roman MM}/{5-digit seq}` via a `sales_pos_sequences`-style counter like `sales_doc_sequences`, or `POS-<short-uuid>` fallback V1 — sequence preferred for audit). Stored `receipt_no` (unique per org, partial unique index) + `receipt_channel` + `receipt_sent_at`.
- **Print path:** `POST` response includes full receipt payload (header org/cashier/session, lines, totals, payment, tendered/change, paper flag). `ReceiptView` renders print CSS (`@media print`, 80mm-friendly) and calls `window.print()` on mount exactly once (guard ref against StrictMode double-fire). Manual Reprint button always available.
- **Email path:** `postExec` (fire-and-forget after settle) loads customer same-org email → `sendPosReceiptEmail(to, receipt)` via `libraries/mail` Mailgun pattern (subject `Receipt {receipt_no}`, text body with lines/totals; HTML optional V2). Missing `MAILGUN_*` → skip send, warn server-side (same fallback as password-reset links), mark `receipt_sent_at=null` + `receipt_channel=email` so UI shows "email pending" with Print-fallback + Resend buttons.
- **Email failure never fails the sale:** send errors only log + leave `receipt_sent_at=null`. Resend `POST .../pos-transactions/:uuid/send-receipt` (perm `view:detail`, completed only, reuses same template; reprint does not re-settle, re-email updates `receipt_sent_at`).
- Env: reuse `MAILGUN_API_KEY / MAILGUN_DOMAIN / MAILGUN_FROM`.

## Acceptance criteria

- [ ] Open twice as same cashier → second returns `already_open`, one row; second cashier unaffected.
- [ ] Session opened yesterday + sale today → stale auto-closed (`auto_closed`), sale requires fresh open (409 otherwise).
- [ ] Close by non-owner → 403; owner close with cash → `closed`, cash snapshotted.
- [ ] System sale short stock → 422, no transaction, no credit consumed; paper sale warehouse-absent → 200 `fulfillment=paper` + receipt flag.
- [ ] Completed sale increments quota `credit_usage` by 1; void does not add credit; void of system sale writes counter `in` movements.
- [ ] Item missing `unit_price` → 400; `discount_pct 101` → 400; tendered < grand_total cash → 400 (or explicit due amount — keep 400 V1).
- [ ] Walk-in checkout returns `receipt_channel=print` + full receipt payload (unique `receipt_no` per org); customer checkout returns `receipt_channel=email`, sends to customer email, sets `receipt_sent_at`; Mailgun down → sale still 201, `receipt_sent_at=null`, UI shows email-pending with Print-fallback + Resend (resend → 200, updates `receipt_sent_at`, no re-settle).
- [ ] `tsc --noEmit` clean; temp `ignoreBuildErrors` build → revert → `pm2 restart my-next-app`; probes `admin@vortexgin.com/admin123`, cleanup afterwards.
